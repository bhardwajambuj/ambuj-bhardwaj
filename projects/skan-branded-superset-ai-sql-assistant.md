## Quick Answer

I led the customization of Apache Superset into a Skan-branded analytics experience with SSO and an embedded SQL Lab assistant. The custom widget gives users two ways to begin analysis without first understanding the underlying data model: browse categorized FAQs with verified SQL that can be inserted directly into the SQL editor, or ask a question in plain English and receive SQL generated by an AI agent grounded in Skan's semantic-layer documentation. We also built an observability framework that records questions, model responses, latency, token consumption and related execution metadata to support quality evaluation, cost optimization, continuous improvement and traceability.

## What Business Problem Did the Project Solve?

Apache Superset provided a capable SQL and analytics environment, but the default experience assumed that users already understood the available schemas, table grain, relationships, metric definitions and query patterns.

This created several barriers:

- New users did not know which datasets or fields to use.
- Common analytical questions repeatedly required help from experienced analysts.
- Users needed examples before they could work confidently in SQL Lab.
- Generic AI-generated SQL could be syntactically valid but inconsistent with Skan's business definitions or data model.
- Without structured logging, the team could not systematically assess AI response quality, latency, token usage, cost or recurring failure patterns.
- The default Superset interface did not provide a fully integrated Skan product and brand experience.

## What Was the Objective?

1. Customize Superset so that it felt like part of the Skan product.
2. Integrate SSO to provide a consistent and controlled sign-in experience.
3. Help users discover trusted SQL without requiring prior data-model knowledge.
4. Organize common questions into categories and subcategories for quick navigation.
5. Allow verified SQL to be inserted directly into the SQL Lab editor.
6. Enable natural-language questions through a semantic-layer-grounded AI agent.
7. Capture detailed interaction and model telemetry for evaluation, traceability and cost optimization.
8. Create a feedback loop for continuously improving the assistant and semantic documentation.

## How Does the User Experience Work?

### 1. Skan-branded and authenticated Superset

- Users access a customized Superset experience aligned with Skan branding.
- SSO provides a consistent authentication flow and reduces the friction of a separate analytics login.
- The analytics experience is integrated with the broader Skan platform rather than presented as an unrelated third-party tool.

### 2. Curated FAQ and verified SQL workflow

- A custom widget is available from SQL Lab.
- Users browse analytical questions through categories and subcategories.
- Each question is mapped to a reviewed and verified SQL query.
- Selecting a question allows the SQL to be inserted directly into the SQL editor.
- Users can inspect, adapt and run the query without first learning the complete data model.

### 3. AI-assisted text-to-SQL workflow

- A user asks a business or analytical question in plain English.
- The AI agent uses Skan's semantic-layer documentation as grounding context.
- The semantic layer supplies business definitions, dataset grain, relationships and approved query patterns.
- The model returns a SQL query aligned with the documented analytical context.
- The generated SQL is made available in the SQL Lab workflow for user review and execution.

### 4. Evaluation and observability workflow

For each AI interaction, the framework captures information such as:

- User question.
- AI agent response and generated SQL.
- Request and response timestamps.
- End-to-end response time.
- Input and output token consumption.
- Model and interaction metadata needed for traceability.
- Information required to evaluate response quality and recurring failure patterns.

The collected telemetry supports model evaluation, prompt and semantic-layer improvement, latency analysis, cost optimization and investigation of individual interactions.

## Architecture Flow

### Curated query path

`SQL Lab -> FAQ Widget -> Category -> Subcategory -> Verified Question -> Approved SQL -> Insert into SQL Editor`

### AI-assisted path

`Plain-English Question -> Semantic-Layer Context -> AI Agent -> Generated SQL -> SQL Lab Editor -> User Review and Execution`

### Evaluation path

`Question + Grounding Context + AI Response + Latency + Token Usage + Metadata -> Interaction Logs -> Quality, Cost and Traceability Analysis`

## Important Architecture Decisions and Trade-offs

### Combine curated and generative assistance

Verified FAQs provide deterministic, trusted answers for common questions. AI-assisted SQL expands coverage to questions that are not predefined. Combining both paths gives users a reliable starting point without limiting them to a fixed catalog.

### Ground the AI agent in the semantic layer

Generic text-to-SQL can generate valid syntax with incorrect joins, grain or metric logic. Grounding the agent in governed definitions and query patterns improves business alignment and makes the semantic layer part of the product architecture.

### Insert SQL for review rather than execute invisibly

Placing the generated or selected SQL into the editor preserves transparency. Users can inspect and modify the query, while normal Superset permissions and database controls remain applicable.

### Organize FAQs by category and subcategory

A flat query list would become difficult to navigate as coverage expanded. A taxonomy makes common questions discoverable and supports controlled content growth.

### Treat AI telemetry as a product requirement

Capturing latency and token usage enables performance and cost management. Recording questions and responses provides traceability and evidence for improving prompts, semantic context and approved SQL patterns.

### Balance customization with platform maintainability

Custom branding and widgets improve the user experience but create an upgrade-maintenance obligation. Changes need version control, testing and compatibility review when Superset is upgraded.

## What Did I Learn?

- The fastest path to self-service combines trusted examples with flexible AI assistance.
- Text-to-SQL quality depends more on semantic grounding than on model capability alone.
- Categories and subcategories turn a SQL library into an accessible analytical product.
- AI observability must include quality, latency, tokens, cost and traceability from the beginning.
- User questions reveal gaps in both the assistant and the underlying semantic documentation.
- Open-source analytics customization creates product differentiation but requires disciplined upgrade and regression testing.

## Frequently Asked Questions

### Does a user need to understand the Skan data model?

No. Users can start from categorized questions and verified SQL, or ask a plain-English question that is interpreted using semantic-layer documentation.

### Does the assistant execute SQL automatically?

The selected or generated SQL is made available in the SQL Lab editor so that it remains visible and reviewable before execution.

### How is the AI agent grounded?

It uses semantic-layer documentation containing business definitions, dataset grain, relationships, approved SQL patterns and analytical context.

### Why capture token usage and response time?

These measures help evaluate model performance, identify latency issues and optimize the cost of the AI-assisted experience.

### How does the system support continuous improvement?

Logged questions, responses, latency and token data provide evidence for improving semantic documentation, prompts, verified queries and model selection while preserving interaction-level traceability.
